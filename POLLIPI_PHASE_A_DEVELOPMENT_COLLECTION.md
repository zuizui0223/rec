# PolliPi Phase-A prospective development collection

Status: **pre-data intake contract for REC-H6 development/calibration evidence**.

This document operationalizes the immediate next step identified in REC issue #20. PolliPi already has a real-camera Phase-A smoke gate, but as of the pinned audit there have been no `workflow_dispatch` runs and no archived physical-camera `tnoa_observation_v1_*.csv` artifact. The next scientific step is therefore data acquisition, not held-out scoring.

## 1. Prospective role comes first

Before starting a physical recording, copy:

`examples/pollipi_development_collection_manifest.json`

and fill the collection metadata.

The first recordings must be labeled `development` or `calibration`. Do **not** collect an unlabeled run and decide later whether it was held out.

Minimum grouping metadata:

- recording day;
- focal scene / focal flower;
- recording block;
- site;
- primary PolliPi device;
- independent reference source;
- comparison session.

These fields implement the Phase-B minimum grouping rule:

`recording day x focal scene/flower x recording block`.

## 2. Physical PolliPi gate

The pinned PolliPi workflow supports a manual physical-camera smoke through `.github/workflows/server-ci.yml` with:

- `run_pi_smoke=true`;
- `real_camera_smoke=true`.

It runs on a self-hosted Raspberry Pi runner and deliberately refuses to stop an active `pollipi.service` automatically. A designated test Pi must therefore be made available intentionally.

The short hardware smoke is useful to verify:

- physical Camera Module access;
- real low-resolution probe acquisition;
- measured probe timing;
- fail-closed TNOA shadow CSV creation;
- artifact upload.

A smoke artifact is **not automatically calibration data**. Only a recording prospectively designated in the collection manifest may enter development/calibration truth preparation.

## 3. Independent reference is mandatory

REC-H6 requires biological truth that is not generated by the tested primary PolliPi chain.

Before a development recording starts, identify the synchronized reference source and set:

`independent_reference_expected = true`.

After the reference material has actually been recorded and safely archived, change:

`independent_reference_recorded = true`.

Do not set this flag based on intention alone.

Primary Phase-A logs can pass their structural audit before the reference file arrives, but they are not eligible for blinded Phase-B truth preparation until the reference material is confirmed recorded.

## 4. REC intake audit

Run:

```bash
python scripts/audit_pollipi_phase_a_development.py \
  tnoa_observation_v1_<run_id>.csv \
  collection_manifest.json \
  --min-rows <prospectively chosen minimum> \
  --require-phase-b-ready \
  --output phase_a_intake.json
```

The audit checks:

- stable PolliPi log and TNOA shadow schemas;
- one run and one primary device;
- non-empty site/flower/session/camera-role/method metadata;
- manifest metadata exactly matches the recorded log;
- chronological and unique probe timestamps;
- real frame availability;
- measured probe timing;
- every row remains `U / observe_only` with no calibrated T/N/O/C/A- support and no applied TNOA action;
- collection was prospectively assigned to development/calibration rather than held out;
- independent reference was planned;
- reference material is actually recorded before Phase-B annotation is allowed.

The caller chooses `--min-rows` **before collection**. REC does not invent a universal duration threshold after seeing a short run.

## 5. Interpretation of the two pass states

`structurally_valid_phase_a_development_log = true`

means the primary PolliPi output is a valid prospectively designated Phase-A development/calibration log.

`suitable_for_phase_b_truth_preparation = true`

additionally requires that the independent reference material has actually been recorded.

Neither status:

- calibrates field TNOA thresholds;
- licenses held-out scoring;
- licenses live adaptive capture;
- establishes REC-H6.

## 6. Phase-B transition

After a Phase-A collection passes intake and reference material exists, prepare blinded Phase-B annotation using the PolliPi tool/contract. Truth labels must be created without exposing target ordinal score, nuisance diagnostics, observability diagnostics, TNOA state/reason or capture-policy recommendations.

Only development/calibration groups may be used to choose field criteria. At least 20% of truth material remains registered for independent double annotation and adjudication occurs before algorithm scoring.

## 7. Current immediate execution order

1. designate a physical test/development Pi and synchronized independent reference;
2. fill the collection manifest **before recording**;
3. perform a short real-camera hardware smoke if the physical path has never been validated;
4. collect a prospectively designated development recording;
5. archive both primary PolliPi and independent reference material;
6. run the REC Phase-A intake audit;
7. create blinded Phase-B truth sheets;
8. accumulate development/calibration groups;
9. freeze field calibration;
10. only then allow untouched held-out H6 scoring.

The repo can now reject a structurally invalid or retrospectively relabeled Phase-A run before it contaminates H6 calibration.
